# 🔐 Realix Security — Vault

Модуль `security/` реализует защиту данных паролем на основе **криптографии**, а
не сравнения строк. Это сознательный выбор: см. раздел «Модель угроз».

## Файлы

| Файл | Назначение |
|------|------------|
| `sha256.asm`  | Потоковый SHA-256 (init / update / final) |
| `hmac.asm`    | HMAC-SHA256 (RFC 2104) |
| `pbkdf2.asm`  | PBKDF2-HMAC-SHA256, dkLen = 64 (RFC 8018) |
| `vault.asm`   | Загрузка `VAULT.BIN`, проверка пароля, расшифровка, публичный API |

Все реализации — зеркало эталона `tools/vault_forge.py`, который проверен на
тестовых векторах NIST/RFC (`python3 tools/vault_forge.py selftest`).

## Криптосхема

```
master   = PBKDF2-HMAC-SHA256(password, salt, iters, dkLen=64)
enc_key  = master[0:32]
mac_key  = master[32:64]
keystream(i) = HMAC-SHA256(enc_key, nonce || BE32(i))   ; PRF в режиме счётчика
plain    = cipher XOR keystream                          ; потоковое шифрование
tag      = HMAC-SHA256(mac_key, nonce || cipher)         ; Encrypt-then-MAC
```

Пароль никогда не сравнивается напрямую. «Проверка» — это успешная проверка
тега целостности: при неверном пароле `mac_key` другой, тег не совпадает, и
открытый текст в принципе не вычисляется.

## Формат `VAULT.BIN` (little-endian)

| Смещение | Размер | Поле |
|---------:|-------:|------|
| 0  | 4  | magic `'RVLT'` |
| 4  | 1  | version |
| 5  | 3  | reserved |
| 8  | 4  | iters (PBKDF2) |
| 12 | 16 | salt |
| 28 | 12 | nonce |
| 40 | 4  | payload_len |
| 44 | 32 | tag (HMAC) |
| 76 | …  | ciphertext |

## Публичный API (`vault.asm`)

```asm
; Загрузить VAULT.BIN с диска и разобрать заголовок.
;   Ошибка (нет файла / плохой magic / большой груз) -> error_handler.
call vault_init

; Запросить пароль (маскированный ввод) и расшифровать груз.
;   Цикл до верного пароля. Успех -> CF=0, груз в vault_plain.
call vault_unlock

; Получить расшифрованный груз.
;   Вывод: ds:si = указатель, cx = длина.
call vault_get_secret
```

Пример (команда `secret` в `kernel16/shell/commands.asm`):

```asm
call vault_get_secret      ; ds:si = груз, cx = длина
; ... вывести cx байт из ds:si ...
```

## Параметры сборки

`VAULT.BIN` генерируется из `Makefile`:

```sh
make VAULT_PASSWORD='my-strong-pass' \
     VAULT_SECRET='top secret payload' \
     VAULT_ITERS=200000
```

Либо вручную:

```sh
python3 tools/vault_forge.py forge --password 'pass' --in secret.bin --out build/VAULT.BIN --iters 200000
python3 tools/vault_forge.py open  --password 'pass' --in build/VAULT.BIN   # проверка
```

## Модель угроз и пределы

Это базовый уровень защиты данных паролем, а не законченная система. Идея
простая: пароль — единственный источник ключа, поэтому без него полезного
груза в открытом виде на диске нет.

Что схема даёт уже сейчас:

- ✅ На диске только шифртекст — доступ к образу диска не раскрывает данные.
- ✅ Пароль не сравнивается, поэтому нет ветки «пускать/не пускать»,
  которую можно снять патчем `jmp`.
- ✅ Стоимость перебора слабого пароля масштабируется через `iters` (PBKDF2).
- ✅ Подмена шифртекста обнаруживается (Encrypt-then-MAC).

Пределы текущей версии (есть что улучшать):

- Пока данные расшифрованы, ключ и открытый текст лежат в ОЗУ.
- Ввод пароля не защищён от аппаратного кейлоггера.
- Стойкость не выше стойкости самого пароля.
